# MeshChat Wire Contract v1\n\nMeshChat uses the BitChat v1 binary packet format on BLE.\n\n## Header\n\n| Offset | Size | Field |\n|---:|---:|---|\n| 0 | 1 | version |\n| 1 | 1 | type |\n| 2 | 1 | TTL |\n| 3 | 8 | timestamp, big-endian |\n| 11 | 1 | flags |\n| 12 | 2 | payload length, big-endian |\n| 14 | 8 | sender ID |\n| 22 | 8 | recipient ID when flag bit 0 is set |\n| ... | N | payload |\n| ... | 64 | Ed25519 signature when flag bit 1 is set |\n\nVersion 1 has a 14-byte fixed header.\n\nFlags:\n- 0x01 recipient present\n- 0x02 Ed25519 signature present\n- 0x04 compressed payload\n- 0x08 route present (v2)\n- 0x10 RSR\n\nPublic broadcast messages use recipient ID FF FF FF FF FF FF FF FF.\n\n## Fragment payload\n\nA FRAGMENT packet (0x20) carries:\n- bytes 0..7: fragment stream ID, big-endian\n- bytes 8..9: fragment index\n- bytes 10..11: total fragments\n- byte 12: original packet type\n- bytes 13..: raw bytes from the original encoded packet\n\nThe reassembled bytes are decoded as a normal MeshPacket. The original packet TTL and signature are preserved.\n\n## Signing\n\nThe signature is Ed25519 over the unsigned packet v1 binary representation with the signature omitted, TTL forced to zero, mutable RSR state cleared, and iOS-compatible PKCS#7-style traffic padding applied to the signing preimage.\n\nRelays may therefore decrement TTL without invalidating the origin signature.\n\n## Identity\n\nThe Noise static X25519 public key is announced in TLV 0x02. The Ed25519 signing public key is announced in TLV 0x03.\n\nThe 8-byte routing peer ID is the first 8 bytes of SHA-256 of the Noise static public key.\n\n## Noise private sessions\n\nPrivate sessions use Noise_XX_25519_ChaChaPoly_SHA256.\n\nHandshake:\n\nA -> B : e\nB -> A : e, ee, s, es\nA -> B : s, se\n\nThe handshake is carried in packet type 0x10; encrypted transport payloads use type 0x11.\n\nNo Internet, Wi-Fi, HTTP, Nostr, or relay server is required.
